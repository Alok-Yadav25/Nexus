# Universal encyclopedia search

Implemented 11 November 2026 in the existing local Next.js / Spring / FastAPI stack. The hero artwork, layout, styling and animation files were not changed.

The eight seeded NEXUS articles are no longer the search or browsing boundary. Every submitted query requests live English Wikipedia matches alongside the local evidence library. Search results open full source articles in NEXUS immediately; neither sign-in nor AI generation is required. Provider pagination exposes further results instead of treating the first page as the full corpus.

The homepage topic fan cycles through Wikipedia's live main-topic classifications (34 categories observed during verification), showing five cards at a time. Each subject opens its actual articles/subcategories with continuation. Search remains open to arbitrary subjects rather than a hardcoded topic list. The fan no longer describes two local entities as the scope of a global subject. Homepage counts now explicitly describe the NEXUS library and graph.

Reader pages retain full text, headings, tables, formulas as source text, numbered citations and reference targets. Other encyclopedia links open the corresponding NEXUS reader; category links open the browser. Original article, contributors/history, revision, provider modification date, retrieval time and license are visible. Wikipedia text is distinguished from reviewed NEXUS claims. Figures remain available in the original article because their licenses require separate attribution. Provider text is parsed into a bounded safe document tree, not injected as HTML.

The Java proxy caches separate provider records for one hour. Outages preserve labeled cached content and original timestamps. Missing articles remain 404; absent search results remain empty results. No fetched article is silently published into the NEXUS claim graph. Approved hosts, DNS pinning, TLS validation, bounded requests, per-service authentication, conservative shared pacing and provider continuation validation remain enforced.

Live checks returned the expected first results for granite, Internet, Shah Rukh Khan, Breaking Bad, Roman Empire and quartz. Further browser coverage includes MrBeast, search pagination, matching local and external results together, subject cycling beyond five cards, and full Granite text with citation navigation in light/dark themes on desktop/mobile. Granite returned revision 1378886812 and 20 table-of-contents headings in the recorded probe. Provider results and revisions naturally change over time.

Final verification: Python 49 tests passed; the 32 existing Java tests and five new controller tests passed; frontend 16 unit tests and the optimized production build passed. A focused production browser run passed 28/28 desktop/mobile scenarios covering universal search, reader references, light/dark layouts, topic cycling, content motion, the retained hero, no-result research behavior, saved articles and collection navigation. An earlier broader development run passed 56/60; the four failures (two stale library-copy assertions and two intermittent mobile account/navigation checks) passed in the final targeted production run. Evidence: `.tools/universal-build.log`, `.tools/universal-java-tests.log`, `.tools/universal-java-controller-tests.log`, `.tools/universal-browser-production.log` and `.tools/universal-live-checks.json`.

Additional live full-article probes loaded Breaking Bad (118 paragraphs, 44 headings) and MrBeast (64 paragraphs, 37 headings) without truncation or executable elements. A nonexistent article returned 404. These checks used the public local proxy, not fixture-only responses.

This provides broad English Wikipedia coverage, rather than claiming a complete index of the internet. Unavailable or nonexistent encyclopedia entries can still be researched separately through the review workflow. The larger NEXUS 3.0 engineering brief has additional unfinished work recorded in `NEXUS3_IMPLEMENTATION.md`.

Provider implementation follows the official [REST page-with-HTML reference](https://www.mediawiki.org/wiki/API:REST_API/Reference#Get_page_with_HTML), [search API](https://www.mediawiki.org/wiki/API:Search), [categorymembers API](https://www.mediawiki.org/wiki/API:Categorymembers), [HTML specification](https://www.mediawiki.org/wiki/Specs/HTML), [reuse terms](https://foundation.wikimedia.org/wiki/Policy:Terms_of_Use#7._Licensing_of_Content) and [robot policy](https://wikitech.wikimedia.org/wiki/Robot_policy). Full-page text uses latest REST rather than routine historical revisions; text attribution remains visible and content is cached separately from NEXUS claims.
