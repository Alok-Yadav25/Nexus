# Security boundary

The application uses Spring Security method authorization, BCrypt cost 12, HTTP-only SameSite=Lax server session cookies, CSRF on mutations, and exact configured CORS origin. Bootstrap credentials come from a private `.env`; registration never grants review or administrator roles. Unknown/invalid credentials receive a common error. Browser API traffic uses a same-origin proxy.

SQL uses JDBC parameters; dynamic table-count names use an allowlist. Cypher uses parameters. Graph bounds, query length, page size, batch size, timeout and download size limits bound requests. Separate minute quotas use HMAC account identities or signed anonymous browser cookies, shared atomic Redis counters, and a bounded local fallback during Redis failure. Client-supplied forwarding headers cannot choose an identity. A broad peer ceiling limits anonymous cookie cycling on sensitive routes. Administrative metrics, research details and saved journeys are role/owner guarded even though published read APIs are public.

Source fetches allow only designated public institutional hosts, HTTPS, port 443, and no URL credentials. Every DNS result must be globally routable. The socket connects to the validated IP while TLS authenticates the original host, preventing DNS rebinding between validation and connect. Redirects re-enter validation, are bounded to three, and bodies to two megabytes. The fetcher checks robots policies, requests no compression, does not execute scripts, and uses OS certificate trust. New source adapters must preserve these constraints.

Research text is data. Extractive citation audit requires exact excerpts. No fetched instructions become application tool calls. Optional server-only Groq synthesis receives bounded quotations and returns strict JSON with claim IDs restricted to the retrieved set. Invalid, truncated, refused or rate-limited output falls back to explicitly extractive notes. No model tool execution is enabled. Generated explanations require explicit reviewer acceptance in addition to individual claim decisions. These controls and the instruction filter do not establish independent factual accuracy.

UI factual prose is rendered as React text, not raw HTML or executable MDX. Source URLs are checked by schema/harvester. A future rich Markdown renderer must retain raw-HTML suppression and safe URL transforms. The graph never runs generated Cypher.

Secrets are excluded by Git and Docker ignore rules. Container application processes run as non-root. Compose ports bind to loopback. Set COOKIE_SECURE=true behind HTTPS and set FRONTEND_ORIGIN and SITE_URL to the deployed origin. The Next proxy supplies a per-response script nonce, CSP, frame denial, MIME protection, referrer and permissions policies; HTTPS_DEPLOYMENT=true additionally enables HSTS. Production scripts have neither unsafe-inline nor unsafe-eval. Inline styles remain permitted for the graph and 3D libraries. The proxy strips untrusted forwarding headers.

The actual servlet prefix binds Secure, HttpOnly and SameSite=Lax cookies. Unknown-account login uses a valid BCrypt hash generated with the same configured encoder, and passwords are bounded to BCrypt's 72-byte input limit. Public revision attribution contains role labels rather than account email addresses. Native modal dialogs isolate background controls and restore triggering focus.

## Before public production use

This is an implementation baseline, not a completed penetration test. Distributed session persistence, account recovery/email verification, stronger adaptive registration abuse controls, broader audit coverage, source parser fuzzing, dependency/container scanning, protected monitoring, and backup restore drills remain release work. The Groq daily request ledger is persistent per AI-service volume, not a cross-replica global budget. Rotate secrets and disable bootstrap credentials after provisioning. Review upstream licenses and resource limits before public deployment.
